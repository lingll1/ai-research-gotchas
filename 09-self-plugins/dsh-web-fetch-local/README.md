# dsh-web-fetch-local

给 `web` seam 注册一个最小的 `WebFetchProvider`，用 Node 内置 `fetch` 抓 http(s) URL，带基础 SSRF 护栏。

87 行，零依赖，只用 `node:dns/promises` 和 `node:net`。

## 为什么自己写而不是用现成抓取

搜索工具拿回来的往往是摘要或重排过的文本，你需要原文才能判断「这句话到底是不是它说的」。一个只做「取回字节」的 provider 职责单一、行为可预测，出问题也好定位是哪一步坏掉。

## 拦住什么

`isBlockedHost()` 在发起请求前检查目标主机：

| 拦 | 值 |
|---|---|
| 回环 | `127.0.0.0/8`、`::1` |
| 任意地址 | `0.0.0.0`、`::` |
| 私网 A | `10.0.0.0/8`、`192.168.0.0/16` |
| 私网 B | `172.16.0.0/12`（第二个八位组 16–31） |
| 链路本地 | `169.254.0.0/16`（含云元数据 `169.254.169.254`） |
| IPv6 ULA / 链路本地 | `fc00::/7`、`fe80::/10` |
| 主机名 | `localhost` |

域名不以字面 IP 出现时，先 `dns.lookup(hostname, { all: true })` 拿全部 A/AAAA 记录，**任意一条**是私网地址就拒绝。只查第一条会被「一公一私」的解析结果绕过。

协议只放行 `http:` / `https:`。`file:` / `gopher:` / `data:` 直接抛错。

## 已知缺口（这些不是疏忽，是没做完）

1. **重定向不复查**。`redirect: 'follow'` 让 fetch 自己跟链，护栏只检查了最初那个 URL。一个公网 URL 302 到 `http://127.0.0.1:8080/`，能穿过去。要堵得手动跟 `redirect: 'manual'` 并在每一跳重新 `isBlockedHost`。
2. **DNS rebinding 窗口**。`lookup` 校验和 `fetch` 实际连接是两次独立解析，中间存在时间差。攻击者控制的 DNS 可以第一次答公网地址、第二次答内网地址。堵法是解析后 pin 住 IP 直连，或者用自定义 `lookup` 传给 agent。
3. **不渲染 JS**。SPA、懒加载内容、前端渲染的正文都拿不到，只会返回一个空 `<div id="app">`。这类页面得用 CDP 浏览器方案。
4. **无 cookie / 无登录态**。抓不到需要登录的页面，也不该抓。
5. **200,000 字符截断**。超长页面（部分 API 文档、issue 长贴）返回 `truncated: true`，正文被切掉。要全文得自己按 Range 分段请求。
6. **返回值是纯文本**。HTML 不转 Markdown，也不抽正文。需要干净正文的话在调用侧处理。

## 用在哪都行，但要知道它弱在哪

如果你的场景只在可信 URL 列表里抓取，上面 1、2 两条不构成风险。如果要抓「用户给的任意 URL」，先补上重定向复查再上线——这是这个实现里最明显的一处「看起来防住了，其实没防住」。
