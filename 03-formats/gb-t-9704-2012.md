# 中文公文格式（GB/T 9704）实务取值

> 标准原文按"每页多少行、每行多少字"来约束，而我们用 Word 只能用字号和行距去凑。所以真正的实务值多半来自实践换算，不是标准里逐字写的。

## 现象

做中文正式文档（报告、申报书、公文），要求"按 GB/T 9704 排版"，然后遇到一连串具体问题：

- 行距到底设多少？标准里没写"28.99 磅"这个数
- 字体写"仿宋"还是"仿宋_GB2312"？
- 标题用"方正小标宋简体"，机器上没这个字体怎么办？
- 三号、二号对应多少 pt？

## 根因

**标准用的是"版面网格"语言，Word 用的是"字号+行距"语言。**

GB/T 9704—2012《党政机关公文格式》的核心约束是版心尺寸与"每面 22 行、每行 28 字"，它不规定行距的磅值。
把"22 行排满 225 mm 版心"换算成 Word 的固定行距，就得到实务中常用的 **28.99 磅**（或 28.8 磅）这类数值 —— 它是**换算结果**，不是标准原文。

理解了这一层，很多"到底哪个对"的争论就消失了：**只要能排成 22 行 × 28 字，就是合规的。**

## 做法

### 一、页面设置

| 项目 | 值 |
|---|---|
| 纸张 | A4（210 × 297 mm） |
| 上边距（天头） | 37 mm ± 1 mm |
| 下边距（地脚） | 35 mm ± 1 mm |
| 左边距（订口） | 28 mm ± 1 mm |
| 右边距（切口） | 26 mm ± 1 mm |
| 版心 | 156 mm × 225 mm |
| 每页行数 / 每行字数 | **22 行 / 28 字** |

### 二、字体与字号

| 层级 | 字体 | 字号 | pt |
|---|---|---|---|
| 大标题 | 方正小标宋简体 | 二号 | 22 |
| 一级标题（一、） | 黑体 | 三号 | 16 |
| 二级标题（（一）） | 楷体 | 三号 | 16 |
| 三级标题（1.） | 仿宋加粗 | 三号 | 16 |
| 正文 | 仿宋 | 三号 | 16 |

字号对照（常用）：初号 42 / 小初 36 / 一号 26 / 小一 24 / 二号 22 / 小二 18 / **三号 16** / 小三 15 / 四号 14 / 小四 12 / 五号 10.5。

### 三、段落

- 正文**首行缩进 2 字符**（不是 2 个空格 —— 用段落的"首行缩进"属性）
- 行距：**固定值 28.99 磅**（实务换算值，用来凑 22 行）
- 段前段后：0
- 对齐：两端对齐

```python
# python-docx 写法要点
from docx.shared import Pt, Cm
from docx.enum.text import WD_LINE_SPACING

p = doc.paragraphs[0]
p.paragraph_format.first_line_indent = Pt(32)          # 2 字符 × 16pt
p.paragraph_format.line_spacing_rule = WD_LINE_SPACING.EXACTLY
p.paragraph_format.line_spacing = Pt(28.99)
p.paragraph_format.space_before = Pt(0)
p.paragraph_format.space_after = Pt(0)
```

### 四、"仿宋_GB2312" 是个误传

这是中文排版里传播最广的一条错误约定：

> ~~"公文正文必须用仿宋_GB2312，标题必须用楷体_GB2312。"~~

**事实**：GB/T 9704—2012 原文只写"仿宋体字"，**从未要求 `_GB2312` 后缀**。
而且 **Windows 系统并不自带**带有该后缀的字体文件。

`_GB2312` 后缀的字体来自早期方正等厂商的 GB2312 字符集版本。当年之所以要指定它，是因为老版本 Windows 中文版的默认宋体字形/编码不理想。现在：

- 系统"仿宋""楷体"（`FangSong` / `KaiTi`）已经覆盖 GB2312 及各扩展字符集
- 指定 `仿宋_GB2312` 在没装该字体的机器上会**静默回退**到别的字体 —— 你看到的和打印出来的可能不一样
- 一旦回退，PDF 里的字体签名就变了，别人拿到文件可能显示错乱

**建议**：脚本里写"仿宋"、"楷体"、"黑体"，不写带后缀的名字。要兼容老环境，做字体存在性探测再回退，而不是硬写一个可能不存在的名字。

```python
# 检查字体是否真的可用（Windows）
import subprocess
def has_font(name: str) -> bool:
    ps = ("Add-Type -AssemblyName System.Drawing; "
          f"(New-Object System.Drawing.Text.InstalledFontCollection).Families "
          f"| Where-Object {{ $_.Name -eq '{name}' }} | Measure-Object | % Count")
    out = subprocess.run(["pwsh", "-NoProfile", "-Command", ps],
                         capture_output=True, text=True).stdout.strip()
    return out not in ("", "0")
```

### 五、页码

- 四号半角宋体阿拉伯数字
- 数字左右各放一条一字线（如 `— 3 —`）
- 单页码居右空一字，双页码居左空一字

## 边界

- **期刊投稿格式与公文格式冲突时，以期刊为准。** 这条极重要 —— 别把公文格式套到投稿稿件上。
- 学校/单位常有"本校模板"，可能与标准有细微出入。**以单位模板为准**，标准是兜底。
- 28.99 磅是为了凑 22 行，如果模板要求不同行数，重算：
  `行距 ≈ 版心高度(mm) ÷ 行数`，再换算磅值（1 mm ≈ 2.8346 pt）。
- 不同 Word/WPS 版本对"固定行距"的渲染可能有细微差别。**交付 PDF 前一定实际数一遍行数。**

## 一句话记法

> **标准管"22 行 28 字"，Word 管"字号 + 行距"。28.99 磅是换算出来的，不是标准原文；"仿宋_GB2312"是误传，标准只写"仿宋体字"。**
