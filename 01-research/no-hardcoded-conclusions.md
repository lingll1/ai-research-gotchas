# 数据可复现：把脚本的结论从代码里赶出去

> 最隐蔽的学术不端不是编数据，而是**脚本里写死了一句"结果符合预期"**。

## 现象

一个分析脚本，跑完打印：

```
均值差异检验：p = 0.032，达到显著水平（p < 0.05），
说明处理组显著优于对照组。
```

一切看起来正常。直到数据换了：p 变成 0.31，脚本输出的那句话**一个字都没变**。

## 根因

脚本里把"判断"和"数据"混在一起：

```python
# 危险写法
print(f"p = {p:.3f}，显著（p < 0.05），说明处理组更优")
```

`p` 是算出来的，但"显著""更优"是**写死的**。作者写这段代码时脑内已经知道结果，于是把结论当字符串拼了进去。
换个数据集，数值会变，结论不会。

更糟的是：这段代码**从来不会抛错**，它只是安静地撒谎。

## 做法

### 一、判决类文字一律现算

凡是承担"判断"功能的文字，必须由数值**分支产生**，不能硬编码：

```python
def describe_p(p: float, alpha: float = 0.05) -> str:
    if p < alpha:
        return f"差异显著（p = {p:.3f} < {alpha}）"
    else:
        return f"差异不显著（p = {p:.3f} ≥ {alpha}），不能据此拒绝原假设"

print(describe_p(p))
```

哪些属于"判决类文字"？一个实用的清单：

- 比值、差值、变化幅度
- 秩、排序、名次
- 极差、最小/最大值
- 窗口的上下限、阈值区间
- 分档/等级标签（"高/中/低"）
- 份数、条目数、样本量
- 任何出现"显著""符合""优于""满足"的句子

### 二、必须单列"是否收敛"

迭代类分析（优化、模拟、数值求解）最危险的不是结果错，而是**没收敛却照样给结论**。

```python
def converged(state_now, state_prev, tol=1e-6) -> bool:
    return abs(state_now - state_prev) < tol * max(abs(state_prev), 1e-12)

if not converged(x, x_prev):
    print("【未收敛】状态量相对变化超过容差，当前结果不能据此判断")
    sys.exit(2)
```

**要点：未收敛一律打印"不能据此判断"，而不是打印一个带了警告的结论。** 前者会让人停下来，后者会被截图进论文。

### 三、需要人工判断的文案，走外部文件

有些话（"本结果支持第 2 章提出的假设"）确实只有作者能写。那就把它从代码里拿出来：

```python
note = json.loads(Path("interpretation.json").read_text(encoding="utf-8"))
print(f"{note['heading']}: {note['text']}")
```

代码只负责**填空**，不负责**下结论**。改文案不用改代码，改代码不会误伤文案。

### 四、输出里带上"这批数据的指纹"

```python
import hashlib, pathlib
h = hashlib.sha256(pathlib.Path("data.csv").read_bytes()).hexdigest()[:12]
print(f"[数据指纹 {h}] n = {len(df)}，均值 {df.x.mean():.4f}")
```

以后看到一张输出截图，能反查它是哪一版数据跑出来的。**这比"结果可信"这四个字有用得多。**

## 边界

- 这条规则针对**会产生对外结论的脚本**（论文分析、报告生成、验收脚本）。一次性的探索脚本不必写成这样，但要记得**探索脚本的结果不能直接进论文**。
- 全自动现算的代价是：**脚本会输出你不喜欢的结论**。这正是它的价值，别为了顺眼把它改回硬编码。
- "现算"不解决口径问题 —— 算得再对，口径不一致还是错（见 [验证纪律](./verification-discipline.md) 第三节）。

## 一句话记法

> **数字可以来自计算，结论也必须来自计算。硬编码的结论等于给自己预先发了一张通行证。**
